# V2.6 stage 4: trusted LAN acceptance

V2.6 stage 3 workflow 45577105835 passed JVM plugin checks and DEX build. The local test server serves only a SHA-256 verified JAR, a generated one-site configuration and checksum file, through a random session path. It performs no upstream requests. It does not run the JAR. It binds loopback by default; private LAN requires an explicit host and --allow-lan. The random path is not authentication and HTTP is unencrypted; only use a trusted isolated LAN. SHA-256 verifies correspondence to the trusted CI checksum, not runtime safety. Use only a Harbor artifact obtained from the official repository build.

1. Download harbor-android-prototype from the successful GitHub Actions run. Extract harbor.jar and sha256.txt.
2. Obtain the corresponding source revision (or newer compatible test-server code). On macOS, cd into the repository root. Run:

       python3 engine/android/serve_test.py --jar /path/to/harbor.jar --sha256 "$(awk '{print $1}' /path/to/sha256.txt)"

3. To use a TV on the same trusted LAN, identify the Mac's actual private IPv4 address and add --host <actual-IP> --allow-lan to that command. Do not use 0.0.0.0, public IPs, port forwarding or a VPS. Copy the printed Test subscription URL to the TVBox test client. Stop the service after testing.
4. Record client name/version, Android version, plugin load, two categories, search Bunny, detail and credit, playback of open demo, second search Steel, and any errors. Save the original subscription before switching. The test config has no live entries. If HTTP LAN or plugin loading is unsupported, record that limitation; do not bypass platform protections.

Automated checks cover checksum, archive structure, host binding policy, HTTP config/JAR/HEAD and missing paths, plus actual CI artifact verification. Actual TV playback and runtime compatibility still require physical testing. Java JSON mapping still limited to bundled reviewed demo titles; CMS and HTML runtime port not complete.
