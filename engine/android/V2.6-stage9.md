# V2.6 stage 9 — opt-in metadata cache

Stage 8 full CI passed (45578854264). Version 3 can opt into a memory-only cache for the fixed first-party network demo endpoint by adding cache:true to its provider (along with allow_network:true). Existing provider configurations without cache retain their prior behavior. No disk cache, background polling or autonomous scheduling. Catalog loads occur on init, not each search. Cache timestamps use monotonic time sampled before the request (conservative age); fresh for 60s, maximum age 300s. Single synchronized cache coalesces concurrent loads. DNS/connection/socket timeout failures allow a still-valid reviewed cached response with 15s retry backoff. Other failures (including TLS, HTTP status, malformed or unreviewed metadata) invalidate cache and propagate to existing isolation. No stale fallback after expiry. Each cached response is rechecked against canonical reviewed data. Diagnostics delivery: snapshot, network, cache_fresh, cache_stale. No arbitrary endpoint or new media support.

Test suite covers fresh hit, stale fallback, backoff, recovery, expiry, TLS and invalid data. Actual device networking and playback are still unverified.

Acceptance gate: stop expanding infrastructure until the existing open-film demo JAR and local test subscription have been exercised on the exact TVBox client. See V2.6-stage4.md. Full generic Java adapter support and the original 755 interface migration are not done. Existing production and preview are untouched.
